# 流式规则

## 冻结边界（`StreamSegmenter`）

只扫描新到达的完整行。以下位置可以冻结（把之前的文本作为独立片段解析一次，之后不再变化）：

1. **空行之后**，并且下一行已经到达，满足：
   - 不在围栏代码块（`` ``` `` / `~~~`）、`:::` 自定义容器、`$$` 或 `\[` 公式块、HTML 原始块（注释、`<pre>`、`<script>`、`<style>`、`<textarea>`、`<?`、`<!X`、CDATA）内部；
   - 下一行没有前导空白（可能是列表项续行、缩进代码块、脚注续行）；
   - 当前片段含列表项时，下一行不是列表标记（否则列表继续并可能变松散）；
   - 下一行不以 `:` 开头（定义列表的释义可以与术语隔着空行）；
   - 下一行不是链接引用定义或脚注定义。
2. **顶层围栏代码块 / 公式块闭合之后**、**ATX 标题之后**，下一行到达且不是 setext 下划线形式（`===` / `---`）。

其它规则：

- 永远不冻结最后一个块（必须看到下一行才能确认前一块已结束）。
- 下一行尚未结束时，如果首字符已经足以判断（不是空白、`-*+[=:`、数字），可以提前冻结；否则等这一行结束或长度达到 16。
- 围栏检测是保守的：任何缩进、引用内的围栏都算，宁可少冻结也不在代码块中间切开。
- 一旦出现链接引用定义或脚注定义，停止冻结；`Complete()` 的整篇重解析会让此前的引用生效。
- 边界单调前进，从不回退。

## 尾部

- 尾部用完整的 remend 补全后交给 Markdig 解析。
- 尾部只是一个以开头行开始、尚未闭合的围栏代码块时，不调用 remend 和 Markdig，直接按行构造 `CodeBlock`（`IsOpen = true`）。

## remend 规则

见 `src/StreamMark.Core/Remend/`（移植自 vercel/streamdown 的 remend，Apache-2.0）。按优先级依次执行：

| 优先级 | 处理器 | 作用 |
|---|---|---|
| 0 | singleTilde | 词字符之间的单个 `~` 转义（`20~25`） |
| 5 | comparisonOperators | 列表项中的 `- > 25` 转义为比较符而非引用 |
| 10 | htmlTags | 去掉末尾未完成的 HTML 标签 |
| 15 | setextHeadings | 末行是 `-`、`--`、`=`、`==` 时加零宽空格，防止误判为 setext 标题 |
| 20 | links | 未完成的链接 / 图片改为占位 URL `streammark:incomplete-link` / `-image`（之后提前返回） |
| 30–42 | 强调 | `***`、`**`、`__`、`*`、`_` 按奇偶补全（跳过代码、公式、URL、HTML 内部和词内标记） |
| 50 | inlineCode | 补全反引号 |
| 60 | strikethrough | 补全 `~~` |
| 70 | katex | 补全 `$$` |
| 75 | inlineKatex | 补全单个 `$`（默认关闭：与货币符号冲突） |

冻结片段和最终整篇解析只启用 singleTilde 与 comparisonOperators。
